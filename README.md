# chassis-ui

A shared, fully typed Vue 3 component library for my homelab and personal projects.
It ships every [shadcn-vue](https://www.shadcn-vue.com) component, unchanged, as one
npm package, so projects stop running `shadcn-vue add` one component at a time.

The reasoning and roadmap live in [PLAN.md](PLAN.md).

> **Status:** early. The library builds, has a playground and is ready to publish,
> but `0.1.0` isn't on npm yet.

## Getting started

### What you need

- **Node.js 22 or 24 (LTS).** Avoid odd-numbered releases like 23: some tooling
  refuses to run on them.
- **pnpm**, via Corepack. The repo pins the exact pnpm version in `package.json`, so
  you don't need to install it yourself:

  ```sh
  corepack enable
  ```

### Install and build

```sh
git clone https://github.com/SethSharp/chassis-ui.git
cd chassis-ui
pnpm install
pnpm build
```

A successful build leaves a `dist/` folder with one entry per component
(`dist/button.js` plus `dist/button/index.d.ts` for its types, and so on), and the
`dist/style.css` projects import.

### Run the playground

```sh
pnpm dev
```

Then open the URL it prints (usually http://localhost:5173). Every component has a
page in the sidebar, showing shadcn-vue's own examples of its variants. The buttons
in the top right switch between light and dark, and between the default and a
"brand" set of tokens, to check theming works.

The playground serves components straight from `src/`, so changes show up without
a rebuild.

## Use it in a project

> chassis-ui isn't on npm yet, so this is how it will work once it is.

Install it alongside Vue and Tailwind v4:

```sh
pnpm add chassis-ui
```

Import the stylesheet after Tailwind in your main CSS file:

```css
@import 'tailwindcss';
@import 'chassis-ui/style.css';
```

That's all the CSS setup. The stylesheet tells Tailwind where the components live,
so you don't need an `@source` line.

Import components by name, the same way shadcn-vue lays them out:

```vue
<script setup lang="ts">
import { Button } from 'chassis-ui/button'
import { Card, CardContent, CardHeader, CardTitle } from 'chassis-ui/card'
</script>
```

### Make it yours

Override any design token after the import, in `:root` for light mode and `.dark`
for dark mode:

```css
:root {
  --primary: oklch(0.55 0.2 260);
  --radius: 1rem;
}
```

chassis-ui doesn't load a font. Set `--font-sans` to whichever font your project
loads.

### Components with extra requirements

`chassis-ui/style.css` uses `@source not`, so projects need Tailwind 4.1 or newer.


| Component | Needs |
|---|---|
| `tooltip` | Wrap your app in `<TooltipProvider>` once |
| `sonner` | `pnpm add vue-sonner`, import `vue-sonner/style.css` once and mount `<Toaster />` |
| `form` | `pnpm add vee-validate @vee-validate/zod zod` |
| `carousel` | `pnpm add embla-carousel-vue embla-carousel` |
| `chart` | `pnpm add @unovis/vue @unovis/ts` |
| `input-otp` | `pnpm add vue-input-otp` |
| `code-block` | `pnpm add shiki` |

These are optional so a project using `Button` never installs a charting library.

## Everyday commands

| Command | What it does |
|---|---|
| `pnpm dev` | Runs the playground |
| `pnpm build` | Builds the library into `dist/`, with type declarations and `style.css` |
| `pnpm smoke` | Installs the built package into a fresh Vite app and checks it typechecks, builds and styles correctly (run `pnpm build` first) |
| `pnpm changeset` | Records a change for the next release |
| `pnpm typecheck` | Type-checks everything without building |
| `pnpm sync` | Pulls the latest components and examples from shadcn-vue, then regenerates the exports |
| `pnpm exports` | Regenerates the `exports` map in `package.json` from the component folders |
| `pnpm examples` | Re-vendors just the playground examples |

## How the project is laid out

```
src/
├── ui/          shadcn-vue components, exactly as upstream ships them
├── extras/      our own components built on top (none yet)
├── lib/utils.ts the cn() class helper
└── style.css    Tailwind theme and design tokens (shadcn-vue manages this file)
playground/
├── examples/    shadcn-vue's own examples, generated by pnpm examples
└── App.vue      the playground shell
scripts/
├── entries.ts   finds every component folder; shared by the build and exports
├── exports.ts   writes the package.json exports map
├── examples.ts  vendors shadcn-vue's examples into the playground
├── theme.ts     turns src/style.css into the dist/style.css projects import
└── sync.ts      re-runs shadcn-vue, then the two scripts above
```

## Ground rules

- **Never edit anything in `src/ui/` or `playground/examples/` by hand.**
  `pnpm sync` overwrites both, so any change there gets lost on the next update.
  Customisations go in `src/extras/`.
- **Change the shipped stylesheet in `scripts/theme.ts`,** not `src/style.css`,
  which shadcn-vue rewrites on sync.
- **Review the diff after a sync** before committing. It's how upstream fixes, and
  occasionally breaking changes, come in.
- **Don't hand-edit the `exports` field** in `package.json`. Run `pnpm exports`
  instead (the build and sync scripts already do).

## Releasing

Releases are driven by [Changesets](https://github.com/changesets/changesets) and
published from GitHub Actions. Nobody publishes from their own machine, apart from the
very first release (below).

1. **In your pull request, add a changeset** for anything that changes what ships:

   ```sh
   pnpm changeset
   ```

   Patch for fixes, minor for new components or features, major for anything that
   breaks an import or a prop. The one-line summary becomes the changelog entry.

2. **Merge the pull request.** The release workflow opens (or updates) a
   "Version Packages" pull request that bumps the version and writes `CHANGELOG.md`.

3. **Merge "Version Packages" when you want to release.** The workflow builds, runs
   the smoke test, publishes to npm with provenance and creates the GitHub release.

Publishing uses npm trusted publishing: GitHub Actions proves who it is to npm
directly, so there's no npm token stored anywhere.

Projects pin a version and upgrade deliberately, so a bad release never reaches
every app at once.

### The first release (one-off)

npm only lets you set up trusted publishing on a package that already exists, so
`0.1.0` is published by hand, from an up-to-date `main` after the first
"Version Packages" pull request is merged:

```sh
git switch main && git pull
pnpm install
pnpm build && pnpm smoke
npm login
npm publish --access public
```

Then, on npmjs.com, open the package's **Settings** and add a trusted publisher:
GitHub Actions, repository `SethSharp/chassis-ui`, workflow `release.yml`. Every
release after that goes through CI.

## Troubleshooting

**`Cannot find module ...corepack\v1\pnpm\12.x\bin\pnpm.cjs`**
Your Corepack is too old for pnpm 12. It only bites outside this repo, since the
repo pins pnpm 10, but you can fix it for good with `npm install -g corepack@latest`.

**`The installed "typescript" package does not provide the JavaScript Compiler API`**
Something pulled in TypeScript 7. The Vue type tooling doesn't support it yet, which
is why the repo pins TypeScript 6. Run `pnpm install` to restore the pinned version.
